# 节点属性面板减法方案

状态：P0–P2 已实施（2026-10-29）；P3 仅完成窄面板单列，字段级校验单独立项
范围：`dsh-plugin/src/editor/inspector.tsx`、`styles.ts`，少量 `page.tsx`
不动：DSL/Schema、执行引擎、数据库、画布节点卡片、校验规则

## 1. 现状诊断：不是信息多，是没有优先级

默认面板宽 312px，选中一个 `subagent` 节点时，从上到下的常驻内容：

| 区块 | 可编辑控件 | 常驻说明段 |
| --- | --- | --- |
| 头部 | 0（只读类型/id/入口） | 0 |
| 基本信息 | 1（标题） | 1 |
| 子 Agent | 11（附加指令、模式、子图、角色、线程、produces、consumes、reportHint、fanOut×3） | 8 |
| 补充说明 | 1（instruction） | 1 |
| 循环与逃生 | 4 | 4 |
| 角色表（全图） | 每个角色 5 个控件 | 1 |
| 底部 | 2 个按钮 | 0 |

结论：**17 个控件 + 15 段说明 + 一张全图角色表**，约 900px 滚动高度。其中真正每节点必填的只有「附加指令」和「执行方式」两项。

具体冗余来源：

1. **说明和字段 1:1 常驻**。每个字段固定占「label + 控件 + 11px 灰字」三行，视觉密度直接翻倍；多数说明是一次性阅读的。
2. **低频字段默认展开**。线程、产物、汇报契约、并行派发、循环与逃生，大部分节点整张图都用不到，却和主输入平级。
3. **全图信息塞进节点面板**。角色表属于 `flow.agents`，和当前节点无关，却在每个节点底部渲染一遍（默认折叠，但仍占位、仍有标题）。
4. **同义字段 / 失效字段**：
   - 标题在头部只读显示，又在「基本信息」里给一个输入框；
   - `instruction` 在 prompt 叫「指令」，在其它类型叫「补充说明」，同一个字段两套 UI；
   - join 的 `instruction` 在运行时被 `aggregateInstruction` 完整覆盖（`shared/src/engine.ts:1609`），填了也不生效；
   - gate 的「出口分支」与画布出口、选项列表三处表达同一件事。
5. **没有概览**。角色、线程、产物、子图、回路这些运行时关键信息全埋在输入框里，必须滚动并逐个读才知道；面板无法回答「这个节点在团队里扮演什么角色」。

根因：字段按「节点类型」平铺，而不是按「使用频率 + 影响范围」分层。

## 2. 目标

选中任意节点后，3 秒内回答五个问题：

1. 这是什么节点？
2. 它叫什么、是不是入口？
3. 它带什么运行时配置（角色/线程/产物/子图/回路）？
4. 它下一步走哪、有几条分支？
5. 它有没有问题？

设计原则：

- **一屏原则**：首屏 ≤ 2 个区块、≤ 3 个控件。
- **全局信息不重复**：角色表移到「图」页签，不再出现在节点页签。
- **说明按需**：placeholder 承担示例；核心字段给 1 行 hint；高级字段的 hint 收进 ⓘ；只有影响正确性的警告常驻。
- **摘要代替展开**：折叠行头显示当前值摘要，不展开也能读到关键配置。
- **失效字段不渲染**：引擎不读的字段不占常驻位置（但用户填过的值不能悄悄消失，见 §4 join）。

## 3. 新信息架构

```
┌──────────────────────────────────────────┐
│ [子 Agent]  评审员                  [入口] │  ← 吸顶头部
│ n3  ⧉ 复制 id                             │
│ 角色 review · 线程 role · 子图 5 节点      │  ← 概览 chips
│ 产物 design→issues · 回路 review≤3 · 2 分支│
├──────────────────────────────────────────┤
│ 附加指令                                  │
│ ┌──────────────────────────────────────┐ │
│ │ 只读不写，产出不超过 20 行…           │ │
│ └──────────────────────────────────────┘ │
│ 执行方式   [inline] [子图] [引用图]        │
│ 子图：5 节点 · 入口 n1        [打开子图]  │
├──────────────────────────────────────────┤
│ ▸ 高级设置 · 3 项                         │  ← 折叠
│   角色与线程 / 产物契约 / 汇报格式 /       │
│   并行派发 / 循环与逃生 / 本步指令         │
├──────────────────────────────────────────┤
│ ▸ 分支（2 条）                            │
├──────────────────────────────────────────┤
│ [设为入口]                        [删除]  │  ← 吸底
└──────────────────────────────────────────┘
```

面板顶部增加页签：**节点 | 图（角色 3）**。选中节点时默认「节点」；「图」页签放全图共享配置（当前就是角色表，后续可放 maxSteps 等）。

### 3.1 头部（吸顶）

- 类型 chip + 标题**就地编辑**（无边框输入，14px/700），不再单列「基本信息」。
- id 小字 + 复制按钮；入口状态用 chip 表达，不再用 disabled 按钮。
- 头部下方是**概览 chips**，只渲染非空项，顺序固定：
  `入口 → 执行方式 → 角色 → 线程 → 产物 → 子图 → 并行 → 回路 → 分支数`。
- 点击 chip：展开对应高级分组并滚动定位、短暂描边 600ms。
- 无配置时不显示「未设置」，避免 chip 变成噪音。

### 3.2 核心区（默认展开）

按节点类型只保留「不填就没法跑」的字段，以及该类型最常改的字段：

| 类型 | 核心区 |
| --- | --- |
| prompt | 指令（含插值提示） |
| tool | 工具名、参数 |
| subagent | 附加指令、执行方式（segmented）+ 当前模式的上下文行 |
| gate | 问题、选项列表（每行含目标） |
| join | 汇聚指令、等待节点 |
| end | 结果 |

### 3.3 高级区（默认折叠）

折叠头显示摘要；展开后两列网格（宽度 < 320px 退化为单列）：

- **角色与线程**：角色下拉、线程输入。摘要：`review · role`。
- **产物契约**：produces / consumes 一行两格。摘要：`design → issues`。
- **汇报格式**：reportHint。摘要：首行截断（如 `payload: verdict/issues`）。
- **并行派发**：from / count / max。摘要：`{{n2.payload.modules}}` 或 `3 项`。
- **循环与逃生**：loopId / maxRounds / iterationLimit / onLimitExceeded。摘要：`review-loop ≤3 → n9`。
- **本步指令**：`instruction` 覆盖项，标注「一般留空，用上游或默认说明」。
- **工具参数 / gate 选项 / join 等待**不在此列，它们是核心区。

### 3.4 连接区

- 仅当出边 > 1 时出现「分支」折叠区，沿用现有条件 / when 编辑器。
- gate 不再单列「出口分支」：目标直接显示在选项行内；未绑定的出边在选项区末尾给一行黄色警告（保留现有兜底逻辑）。
- 单出边不显示任何分支 UI。

### 3.5 底部

吸底：设为入口 / 删除节点。已是入口时左侧显示静态「当前入口」chip，减少一个 disabled 控件的存在感。

## 4. 字段去留决策

| 类型 | 常驻 | 高级（折叠） | 合并 / 移出 / 隐藏 |
| --- | --- | --- | --- |
| prompt | 指令 | 循环与逃生 | 标题 → 头部 |
| tool | 工具名、参数 | 本步指令、循环与逃生 | 标题 → 头部 |
| subagent | 附加指令、执行方式 + 上下文行 | 角色与线程、产物契约、汇报格式、并行派发、循环与逃生、本步指令 | 两个「内嵌子图」区块合并；标题 → 头部 |
| gate | 问题、选项（含目标） | 本步指令、循环与逃生 | 删除独立「出口分支」区；标题 → 头部 |
| join | 汇聚指令、等待节点 | 本步指令、循环与逃生 | 标题 → 头部 |
| end | 结果 | — | 标题 → 头部；无循环区 |

说明：

- **join 的本步指令**保留在高级但加注「运行时会被汇聚指令覆盖，通常不用填」，而不是直接删掉——避免用户已填的内容无声消失。
- **subagent 的本步指令**同理放高级：它参与 `view.instruction`，但多数场景由附加指令 + preamble 承担。
- **gate 的本步指令**留空时引擎有默认转达话术（`engine.ts:1536`），所以放高级。
- **角色表**整体移到「图」页签，节点页签不再渲染。

## 5. 交互细节

### 5.1 执行方式合一

现在 `mode` 是下拉，`subflow` / `inline` 又各有一个「内嵌子图」区块，文案重复。改为：

```
执行方式  [inline] [子图] [引用图]
```

下方只渲染当前模式的一行上下文：

- inline：不占行；
- 子图：`5 个节点 · 入口 n1` + 「打开子图」/「创建子图并打开」；
- 引用图：下拉选图（含失效值兜底）。

切换逻辑保持现状：切到子图且没有 `subflow` 时补一张最小合法子图（复用 `makeSubflow`）。

### 5.2 hint 策略

| 场景 | 处理 |
| --- | --- |
| 核心字段 | 控件下方 1 行 11px hint（最好 ≤ 24 字） |
| 高级字段 | hint 收进 label 右侧 ⓘ 的 `title`，不占行 |
| 会影响数据正确性的警告 | 常驻显示（选项未连接、回路无控制器、被引用节点不存在） |
| 示例 | 交给 placeholder，不重复写进 hint |

### 5.3 校验

- 选中节点存在 issue 时，头部下方显示一条可展开的「2 个问题」汇总（按 `issue.nodeId` 过滤），点击定位到字段/展开对应分组。
- 页头现有校验浮层保留，两者不冲突。
- 字段级红框需要 `ValidationIssue.field`，放 P3，不在本次必做范围。

### 5.4 状态与记忆

- 折叠分组的展开状态按节点类型记忆（组件内 state 即可）；P3 可选写入 localStorage。
- 未选中节点时保留快捷提示，但压缩成 2 行 + 一个「新建节点」入口（可选）。

## 6. 视觉规范

- 头部高 56px，sticky top；底部高 44px，sticky bottom。
- 只剩 3 个一层区块（核心 / 高级 / 分支），区块间 12px + 1px hairline；去掉大写 + letter-spacing 的 section title（层级由折叠头和间距表达）。
- 字号三级：标题 14/700、字段名 12/700、说明 11/400；输入 12px。
- 折叠行 30px，chip 22px，圆角 8/999。
- 间距 5 / 8 / 12 三档，不再出现 10px 这类中间值。

## 7. 分阶段落地

### P0 结构重排（0.5 天）

- 标题并入头部，删除「基本信息」。
- 统一 `instruction` 的 UI 与位置（prompt 核心，其余高级）。
- 执行方式合并为一个控件 + 模式上下文行。
- gate 出口并入选项行，删除「出口分支」区。
- 角色 / 线程 / 产物 / 汇报 / 并行合并进「高级设置」折叠。
- 落地 hint 策略。

验收：subagent 首屏只有 2 个控件、高度 ≤ 420px；所有字段仍可编辑；DSL 输出不变；`typecheck` + `test` + `build:plugin` 通过。

### P1 概览与吸顶（0.5 天）

- 新增纯函数 `summarizeNode()`（放 `model.ts`）生成 chip 与折叠摘要，并补单测。
- 点击 chip 展开/定位；头部与底部吸顶；id 复制。

验收：角色、线程、产物、子图、回路、分支数 6 类信息无需滚动即可读到。

### P2 图页签（0.5 天）

- inspector 顶部 tab：节点 / 图。
- 角色表迁到「图」，节点页签不再渲染。
- 节点问题汇总条。

验收：任意节点面板中不再出现全图角色表；切换节点不改变「图」页签内容。

### P3 收尾（可选）

- `ValidationIssue.field?: string`，关键错误贴字段（需要改 `shared/src/validate.ts` 的 err/warn 调用，影响面较大，单独立项）。
- 折叠状态记忆、窄面板单列、键盘可达性（Tab 顺序 / Esc 收起）。

## 8. 不做与风险

不做：DSL 字段增删、引擎行为、DB 迁移、画布节点样式、模板插入逻辑、校验规则。

风险与对策：

- **折叠降低可发现性**：用 chips + 折叠头摘要补偿；首次打开高级区时给一次性说明（P3）。
- **老图数据看不见**：join/subagent 的 instruction 不删除，只降级到高级并注明覆盖关系。
- **面板宽度 240px 时两列网格拥挤**：< 320px 退化为单列。
- **概览 chips 太长**：单行横向滚动 + tooltip 显示完整值，最多展示 5 个，其余收进「+2」。

## 10. 实施记录（2026-10-29）

已落地：

- 头部合并标题 / id / 入口 / 概览 chip；标题就地编辑，id 可复制。头部、页签、底部动作都固定在滚动区之外（不随内容滚动），中间只有字段区滚动。
- 概览 chip 单行横向滚动（不换行），避免 5–6 个 chip 把头部撑成两三行；完整值在 `title` 里。
- 核心区按类型收敛：prompt=指令；tool=工具名+参数；subagent=附加指令+执行方式；gate=问题+选项（目标写进选项行）；join=汇聚指令+等待；end=结果。
- 高级设置折叠为 5 组（subagent）：角色与线程、**产物与汇报**、并行派发、循环与逃生、本步指令。与原方案相比把「产物契约」和「汇报格式」合成一组，减少一行折叠头。
- 执行方式改为分段控件，inline / 子图 / 引用图各自只显示当前模式一行上下文。
- gate 删除独立「出口分支」区；未绑定选项的出边作为选项区末尾黄色警告。
- 删除「基本信息」「补充说明」两个恒常区块；join 的本步指令降级到高级并注明会被汇聚指令覆盖。
- 面板顶部页签「节点 / 图」；角色表迁到「图」，节点页签不再渲染。
- 选中节点的校验问题在面板头部下方汇总（`Inspector.issues`，由 `page.tsx` 按 `nodeId` 过滤）。
- 折叠状态用组件内 state 记忆（同一会话内跨节点保留）；窄于 280px 时两列网格退化为单列。
